# K230 钢珠训练台动态改造设计

## 目标

把现有三模型并排页面改成真正可用的训练控制台：默认只展示当前正在训练的模型，每个模型拥有独立子页面；完成或失败的训练进入历史记录并永久保留指标、终端和曲线。

页面服务于本机模型训练监控。第一眼必须回答四件事：训练是否还活着、整体完成多少、当前轮完成多少、模型指标是否继续提升。

## 已批准的视觉方向

采用 C 方案“安静控制室”。保留 Claude 风格的暖黄色纸张底色、陶土橙重点色和深炭色终端，但科技感来自真实遥测、细网格、同步状态和运动反馈，不使用霓虹光污染或装饰性光球。

页面唯一的趣味焦点是右上角小猫：

- 运行中：透明背景小型精灵图沿短轨道往返跑动；
- 正常收到新日志：保持跑动并显示绿色同步状态；
- 日志延迟：减速并显示等待状态；
- 训练完成：历史页面中静坐；
- 训练失败：停下并显示明确的失败状态；
- 系统启用“减少动画”时：所有运动停止，小猫保持静态。

## 信息架构

顶部使用两个一级标签：

1. `运行中`：只包含日志仍持续写入、尚未出现完成或失败终止标记的训练。
2. `历史记录`：包含正常完成、自动早停、人工停止和异常退出的训练。

每个模型是独立子页面，并拥有可复制的 URL 状态，例如：

```text
/?view=active&run=steel_ball_reference_yolo26n_1024_live
/?view=history&run=steel_ball_reference_yolo11n_1024
```

点击模型标签只切换当前子页面，不整页刷新。浏览器前进、后退和刷新后仍保留当前模型。

## 单模型页面结构

从上到下固定为：

1. 顶栏：产品名、运行中/历史记录切换、模型标签、小猫和同步时间。
2. 模型标题：模型家族、输入尺寸、设备和当前状态。
3. 双进度区：总体训练进度、当前轮次进度。
4. 指标区：mAP50、精确率、召回率、平台期计数。
5. 实时终端：结构化进度行和最近原始输出。
6. 页面底部曲线：每轮 mAP50、精确率和召回率。

页面采用未嵌套的全宽分区。终端是唯一深色面板；进度与指标使用平面边框分隔，避免卡片套卡片。

## 训练状态与历史归档

服务端不依赖额外进程管理库，通过训练目录判断状态：

- 日志文件最近 12 秒内持续更新：`running`；
- 输出包含正常训练完成或目标平台期早停标记：`completed`；
- 输出包含 traceback、runtime error，且日志停止更新：`failed`；
- 有结果和权重但没有活动日志：`completed`；
- 目录存在但尚未写入第一批数据：`starting`。

所有非 `running/starting` 状态自动进入历史记录。历史记录只读，不删除原始文件。失败训练保留最后异常，正常完成训练展示最佳轮和最终轮。

## 真实进度计算

从训练输出解析：当前轮、总轮数、当前批次、总批次数、ETA、GPU 内存和损失。

当前轮进度的真实锚点为：

```text
batch_index / batch_total × 100
```

总体进度包含当前轮内部进展：

```text
(completed_epochs + epoch_progress) / total_epochs × 100
```

两个百分比均显示两位小数。为了避免每个批次之间数值静止，浏览器根据最近 20 个批次的平均耗时做线性插值，但必须遵守：

- 插值永远不能达到或超过下一批次的理论百分比；
- 收到新批次时立即校准到新真实锚点；
- 日志超过 5 秒没有变化时冻结，不继续虚增；
- 断开连接或训练停止时立即冻结；
- 辅助文字明确标注“批次间平滑估算”。

## 进度动画

进度条高度为 12–14px，提供三层运动：

- 填充宽度以短时线性过渡跟随两位小数；
- 填充内部使用低对比度斜纹流动高光；
- 前沿使用小型呼吸点标出当前进度位置。

动画速度随最近批次吞吐轻微变化，但不影响百分比计算。日志停止时高光和呼吸点一起暂停。

## 终端渲染

终端分为结构化状态行和原始日志尾部：

- 结构化行固定展示轮次、批次、GPU、box loss、cls loss、ETA；
- 原始日志保留最近 80 行，可滚动、复制，并自动跟随底部；
- 用户主动向上滚动后暂停自动跟随，回到底部后恢复；
- ANSI 控制序列被清理，Rich/TQDM 的回车刷新合并为稳定行；
- traceback 使用醒目的错误色，但不隐藏第一条异常。

终端每秒请求一次数据。请求成功时更新心跳；连续三次失败后显示“监控连接中断”，保留最后画面，不清空数据。

## 曲线

曲线位于页面底部，使用响应式 Canvas 绘制：

- Y 轴显示 0–1 指标范围，X 轴显示轮次；
- 显示浅色水平网格和真实数据点；
- mAP50、精确率、召回率使用陶土橙、冷绿色和金色区分；
- 当前轮使用竖向虚线标记；
- 鼠标或触摸悬停显示该轮三个指标的精确值；
- 新一轮写入后只做短时路径过渡，不重建整个页面；
- 数据不足两轮时显示数据点和等待下一轮提示，不绘制误导性趋势线。

## 动态更新

页面不再每两秒整体替换 DOM。首次加载创建结构，后续只更新发生变化的文字、进度宽度、终端增量和 Canvas 数据。

动态元素包括：同步时间、心跳点、两位小数进度、批次速率、ETA、指标数值过渡、终端光标和曲线路径。所有动态均支持 `prefers-reduced-motion`。

## API 数据结构

每个训练任务至少返回：

```json
{
  "id": "steel_ball_reference_yolo26n_1024_live",
  "name": "YOLO26 1024",
  "status": "running",
  "updated_at": "20:44:33",
  "epoch": {"current": 3, "total": 60},
  "batch": {"current": 568, "total": 703, "eta_seconds": 43},
  "metrics": {"map50": 0.972, "precision": 0.929, "recall": 0.928},
  "plateau": {"goal_reached": false, "stalled": 0, "patience": 7},
  "series": {"epochs": [1, 2], "map50": [0.964, 0.972]},
  "terminal": "..."
}
```

首页 API 同时返回 `active` 和 `history` 两组，并保持训练目录顺序稳定。

## 响应式与可访问性

- 桌面端双进度并排，终端全宽，曲线全宽；
- 窄屏端进度纵向排列，指标两列，终端保持可横向滚动；
- 所有标签和模型切换支持键盘焦点；
- 状态不仅依赖颜色，同时包含文字；
- Canvas 曲线提供等价的隐藏数据表供辅助技术读取；
- 小猫为装饰元素，不抢占屏幕阅读器焦点。

## 验收标准

1. 页面默认只显示活动训练，已完成或失败训练可从历史记录打开。
2. 每个模型拥有独立可恢复 URL。
3. 本轮和总体百分比显示两位小数、平滑变化，并且永远不领先真实下一批次。
4. 日志停止后 5 秒内所有估算进度冻结。
5. 终端能正确渲染当前 Ultralytics 输出和 traceback。
6. 曲线位于底部，坐标、数据点、悬停值和当前轮标记可用。
7. 动态刷新不导致页面滚动位置、终端选择或布局跳动。
8. 小猫按运行、等待、完成、失败状态切换，并尊重减少动画设置。
9. 桌面和手机宽度下无文字溢出或元素重叠。
10. Dashboard 单元测试覆盖状态分类、日志解析、进度上限和历史归档；浏览器测试覆盖标签切换与实时更新。
